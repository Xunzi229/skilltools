# 本地 Skill 管理器设计

## 1. 目标

开发一个基于 Tauri 2 的桌面应用，统一管理本机以下目录中的 Skill：

- `~/.cursor/skills`
- `~/.claude/skills`
- `~/.codex/skills`

首版提供 Skill 列表、详情、搜索与筛选、手动备份、删除前自动备份、暂停、恢复和备份历史恢复能力。

## 2. 技术选型

- 桌面容器：Tauri 2
- 前端：React + TypeScript
- 本地文件服务：Rust
- 数据持久化：应用数据目录中的 JSON 索引及版本化备份文件

React 仅负责界面、交互状态和命令调用。所有文件扫描、路径校验、移动、复制、删除和恢复操作均由 Rust 服务执行。

没有采用前端直接调用文件插件，因为路径权限和业务规则容易分散；没有采用 Node.js Sidecar，因为它会增加运行时、进程通信和打包复杂度。

## 3. 界面设计

主界面采用三栏主从布局：

### 3.1 左栏

- 全部 Skills
- Cursor
- Claude
- Codex
- 已暂停
- 备份记录

每个分类显示数量。底部提供刷新入口。

### 3.2 中栏

- 按名称和描述搜索
- 按来源和状态筛选
- 展示名称、摘要、来源、状态
- 点击后在右栏打开详情

### 3.3 右栏

- 名称、描述、来源、状态和绝对路径
- 渲染后的 `SKILL.md`
- Skill 目录文件清单
- 暂停或恢复、手动备份、删除操作

删除和恢复使用二次确认弹窗。操作进行时禁用相关按钮，避免重复提交。

### 3.4 备份记录

- 按 Skill 展示备份历史
- 显示备份原因、创建时间、原始路径和来源
- 支持将指定版本恢复到原始位置

## 4. 核心模型

### 4.1 Skill

- `id`：由来源和规范化原始路径生成的稳定标识
- `name`：优先取 `SKILL.md` frontmatter 中的名称，否则取目录名
- `description`：优先取 frontmatter 中的描述
- `provider`：`cursor`、`claude` 或 `codex`
- `status`：`active` 或 `paused`
- `originalPath`：启用状态下的位置，暂停后仍保留
- `currentPath`：当前实际位置
- `skillMarkdown`：`SKILL.md` 原文
- `files`：目录内的相对文件清单
- `warnings`：解析失败、缺少文件或符号链接等非致命问题

### 4.2 Backup

- `id`：唯一备份标识
- `skillId`
- `skillName`
- `provider`
- `reason`：`manual` 或 `before_delete`
- `createdAt`
- `originalPath`
- `archivePath`
- `checksum`

### 4.3 PauseRecord

- `skillId`
- `provider`
- `originalPath`
- `pausedPath`
- `pausedAt`

## 5. 文件与数据组织

应用通过 Tauri 的系统路径 API 获取应用数据目录，不硬编码操作系统路径。目录结构如下：

```text
app-data/
├── config.json
├── paused-index.json
├── backup-index.json
├── disabled/
│   ├── cursor/
│   ├── claude/
│   └── codex/
└── backups/
    └── <skill-id>/
        └── <timestamp>-<backup-id>/
```

备份使用完整目录副本，保留 Skill 内全部文件和相对结构。索引文件使用“写入临时文件、同步、原子替换”方式更新。

## 6. Rust 服务边界

前端通过类型化 Tauri Command 调用以下能力：

- `scan_skills`：扫描启用目录和停用目录
- `get_skill_detail`：读取并解析指定 Skill
- `pause_skill`：移动到应用停用目录并记录原路径
- `resume_skill`：恢复到原路径
- `create_backup`：创建手动备份
- `list_backups`：读取备份历史
- `restore_backup`：恢复指定备份
- `delete_skill`：自动备份成功后删除

每个命令返回结构化成功数据或包含错误码、中文消息和可选上下文的错误对象。

## 7. 关键流程

### 7.1 扫描

1. 规范化三个 Skill 根目录。
2. 读取每个根目录的直接子目录，不将普通文件识别为 Skill。
3. 读取子目录中的 `SKILL.md`。
4. 解析 YAML frontmatter 和 Markdown；解析失败时保留条目并附加警告。
5. 合并停用索引中的 Skill。
6. 返回按名称排序的列表。

### 7.2 暂停

1. 校验 Skill 位于允许的启用根目录中。
2. 检查目标停用位置不存在冲突。
3. 将完整目录移动到 `disabled/<provider>/`。
4. 原子更新停用索引。
5. 返回更新后的 Skill。

如果跨文件系统导致原子重命名不可用，则复制到临时目录，校验文件清单与内容校验值，完成后再删除源目录。

### 7.3 恢复暂停项

1. 从停用索引取得原始路径。
2. 校验原始路径属于对应来源的 Skill 根目录。
3. 如果目标已存在则停止，不覆盖现有目录。
4. 将目录移回原始位置。
5. 原子移除停用记录。

### 7.4 手动备份

1. 校验 Skill 当前路径。
2. 复制完整目录到临时备份目录。
3. 生成文件清单和校验值。
4. 将临时目录原子移动为正式备份目录。
5. 原子更新备份索引。

### 7.5 删除

1. 显示二次确认。
2. 执行原因标记为 `before_delete` 的自动备份。
3. 仅在备份及索引写入成功后删除 Skill 目录。
4. 如果删除的是暂停项，同时移除停用记录。
5. 任一步骤失败都返回错误，并尽可能保留原 Skill。

### 7.6 从备份恢复

1. 校验备份目录和校验值。
2. 确认恢复目标属于允许的 Skill 根目录。
3. 目标已存在时停止并提示冲突，不自动合并或覆盖。
4. 复制到目标同级临时目录并校验。
5. 原子移动到正式目标位置。

## 8. 安全约束

- Rust 服务只允许操作配置的三个 Skill 根目录、应用停用目录和备份目录。
- 所有输入路径先规范化，再进行父子路径边界检查。
- 不接受前端传入的任意删除路径；操作通过已扫描出的 `skillId` 或 `backupId` 定位。
- 符号链接可以展示，但不递归跟随到允许目录之外。
- 不覆盖已存在的 Skill、停用项或恢复目标。
- 所有破坏性操作写入结构化日志，但不记录 Skill 文件内容。

## 9. 异常处理

需要区分并展示以下错误：

- 根目录不存在或不可读
- `SKILL.md` 缺失或 frontmatter 无法解析
- 路径越界
- 目标名称冲突
- 权限不足
- 磁盘空间不足
- 备份复制或校验失败
- 索引损坏
- 源文件在操作期间发生变化

扫描单个 Skill 失败不阻断整个列表。暂停、恢复、备份和删除失败时保留当前界面状态，显示可重试的中文错误。

- 删除前自动备份

## 11. 首版范围外

- 在线 Skill 市场
- Skill 内容编辑
- 云同步
- 自动更新 Skill
- ZIP 导入导出
- 多选批量操作
- 自动清理或保留期策略
- Windows 和 Linux 安装包验收

架构不依赖 macOS 专有文件 API，后续可以补充 Windows 和 Linux 验证。

## 12. 验收标准

1. 应用能展示三个默认目录内的有效和异常 Skill。
2. 用户能按来源、状态、名称和描述找到 Skill。
3. 详情能展示元数据、Markdown、路径和文件清单。
4. 暂停后对应 Agent 的默认 Skill 目录中不再存在该 Skill。
5. 恢复后 Skill 回到原路径，内容保持一致。
6. 用户能创建多个手动备份并查看历史。
7. 删除必须在自动备份成功后执行。
8. 用户能从任一有效备份恢复，且不会覆盖已有目录。
9. 路径越界、权限不足和目标冲突不会造成源数据丢失。
10. 前端测试、Rust 测试、类型检查和 Tauri 打包全部通过。
