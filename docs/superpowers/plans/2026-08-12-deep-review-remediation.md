# 深度审查整改方案

## 目标

以最小、可验证的改动修复当前确认存在的数据完整性、跨平台、状态一致性和构建可复现问题。模型服务配置、用户选择 ZIP 路径等既有产品约束保持不变，不把未证实的安全假设混入本次整改。

## 实施顺序

### 1. 构建与核心边界

- 同步 `Cargo.lock` 中应用版本和 `tauri-plugin-single-instance` 依赖。
- 单项与批量迁移统一拒绝暂停 Skill。
- Skill 元数据和重命名写入复用文件软链边界校验。
- 迁移替换链接改为可回滚事务，避免建链失败后丢失 provider 源目录。

### 2. 备份与跨平台路径

- 备份记录显式保存归档类型；旧记录仅在归档只含 marker 时按软链兼容恢复。
- 扫描统一要求标准文件名 `SKILL.md`。
- Windows 风格路径不区分 ASCII 大小写，POSIX 路径保留大小写；前后端规则一致。
- Windows 相对链接目标相对目标链接父目录解析。
- provider 根改变后，安装迁移到当前根；只清理已验证仍指向同一库源的旧链接。

### 3. 翻译稳定性

- 所有字符串截断落在 UTF-8 字符边界。
- 缓存键加入版本、Base URL、模型和 API Key 摘要。
- 错误响应先完整脱敏，再安全截断。

### 4. 前端状态

- AI 标签草稿合并现有标签和建议标签，应用时写入最终集合。
- 批量计数、确认文案和请求统一使用当前可见 ID。
- 库详情切换或加载失败时不展示旧详情。
- 批量命令失败进入可见错误状态，不产生未处理 Promise。
- 分组排序值由后端在事务内分配。
- 安装、卸载、迁移、修复和预设操作增加 single-flight 防重入。

## 回滚原则

- 任何会删除或重命名用户目录的操作，必须先保留同目录临时副本。
- 新链接、索引和文件写入失败时，按逆序恢复旧链接、旧目录和旧内容。
- 回滚失败返回同时包含原始错误与回滚错误的 `RollbackFailed`。
- 不自动删除真实目录、来源不匹配链接或无法验证归属的路径。

## 验证

- Rust：软链越界、暂停迁移、迁移/重命名故障回滚、备份类型兼容、POSIX 大小写、Windows 相对链接、provider 根变化、UTF-8 边界、缓存身份。
- 前端：AI 最终标签集、隐藏选择、详情失败、批量拒绝、连续分组顺序、操作防重入。
- 完整执行：
  - `npm test`
  - `npm run typecheck`
  - `npm run build`
  - `cargo fmt --check`
  - `cargo test --locked`
  - `cargo clippy --all-targets -- -D warnings`

正式发版仍由 `.github/workflows/release.yml` 的 GitHub Actions 完成。
